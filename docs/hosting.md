# Hosted deployment: opengraph.works

Source: S:/GitHub/open-graph-preview
Local instance: D:/laragon/www/og

1. Use PHP compatible with composer.lock (current dependencies run on PHP 8.4), Composer and cURL/DOM/mbstring/GD/OpenSSL/PDO SQLite. Serve only public/ with HTTPS.
2. composer install --no-dev --optimize-autoloader
3. Copy .env.production.example to .env. Generate a unique APP_KEY using php artisan key:generate.
4. Create the configured database, run php artisan migrate --force and create the administrator with php artisan opengraph:admin --email=you@example.com --name="Your Name". Configure the actual instance in /admin. Existing opengraph.works settings: hosting in Bremen, Germany; webserver logs 7 days; Matomo raw visit data 180 days; Sentry data 30 days. Aggregated Matomo statistics are retained indefinitely. Backend settings override LEGAL_* defaults. New instances must provide their own operator and legal pages.
5. php artisan opengraph:check-production
6. php artisan optimize:clear; php artisan config:cache; php artisan route:cache; php artisan view:cache

Matomo: configure your own HTTPS instance URL and site ID in /admin/settings/monitoring. Consent required before any tracker load. No tracking cookies, browser-feature detection, referrer, submitted URLs or query parameters. Enable IP masking in Matomo administration and configure automatic raw-data cleanup according to the declared period. Enter the actual hosting location in the legal settings. Matomo's own webserver/access logs need the same privacy review. Do not claim this was changed by the application.

Sentry: official Laravel SDK. DSN fields in both example environments are empty. Configure your own DSN in the backend. Errors are rebuilt with sanitized messages and frames, no request/user/context data. Only allowlisted operational logs and metrics are accepted. The old/deprecated Metrics API is a no-op; this app uses traceMetrics() for Application Metrics. No session replay, browser SDK, profiler or outgoing-request tracing.
Metrics: opengraph.requests, opengraph.duration (milliseconds), opengraph.preview_requests, opengraph.preview_failures, opengraph.check_failures and opengraph.check_warnings.
Monitoring is disabled locally by default. Integration tests in Sentry use environment integration-test.

No server-side check URL history. Browser-only history stores up to 20 URLs in localStorage, can be disabled or cleared, and is never synchronized with the server. Input URLs travel only in POST bodies. Disable request-body capture in the reverse proxy, WAF, APM and webserver. Webserver access logs should avoid query strings and never record POST bodies. Configure rotation/deletion according to LEGAL_WEB_LOGS_DAYS. Application daily log retention defaults to seven files/days when LOG_DAILY_DAYS=7; messages and contexts are filtered. Laravel storage/framework/sessions contains technical session state only and needs periodic garbage collection.

Hosted mode disallows local/private IPs and non-80/443 ports, checks redirect targets and pins verified public addresses in cURL. PREVIEW_ALLOW_PRIVATE_TARGETS=true is for the isolated local installation only.

Legal pages: /de/impressum, /en/impressum, /de/datenschutz and /en/datenschutz with shared UI. Language homepages are /de/ and /en/. Legacy ?lang= links redirect to the matching language path. Provider details are instance-specific and managed in the backend; distribution defaults do not identify kuhla.tech as the operator.
The privacy notice describes necessary session/local settings, optional Matomo consent, Sentry processing, target-site requests, rights and recipients. Hosting and retention details reflect the operator confirmations. Review your Sentry processor agreement before publication.

## Search engine verification and sitemap

Set GOOGLE_SITE_VERIFICATION and BING_SITE_VERIFICATION in the hosted .env to the content values supplied by the HTML-tag verification methods in Google Search Console (URL-prefix property) and Bing Webmaster Tools. Do not paste the entire meta tag. Empty values omit the tags. Run php artisan config:cache after changes, then verify the public homepage in each service. Google domain properties require DNS verification instead.

Submit https://opengraph.works/sitemap.xml to both services. The generated XML includes the three public pages in German and English with reciprocal hreflang links. URLs use APP_URL and /de/ or /en/ language prefixes. /robots.txt is generated by Laravel and points to the sitemap; remove any old public/robots.txt during deployment so the webserver does not shadow the route. Submitted preview URLs are never included.

## Backend deployment

The backend requires a database. SQLite defaults to database/database.sqlite; PDO SQLite is required. Never publish that file. For existing installations, preserve APP_KEY, run migrations, install Composer dependencies, clear configuration/route/view caches, then rebuild them. Settings use APP_KEY encryption; restoring a database with a new key will make settings and 2FA data unreadable.

Administrator bootstrap: php artisan opengraph:admin --email=you@example.com --name="Your Name". The private one-use password link expires after 60 minutes. No password or public registration is shipped. Configure TOTP and recovery codes or HTTPS passkeys in /admin/security. Back up your recovery codes. Additional administrators are created with the same CLI command.

Settings, search verification, service credentials, branding and legal content are stored in instance_settings. Infrastructure is intentionally kept in .env. Uploads live in storage/app/public/branding and are served by the application without requiring a storage symlink. Use matching APP_URL on both CLI and web so signed setup links and WebAuthn origins agree.

If an unused setup link expires, run php artisan opengraph:admin --email=you@example.com --renew-setup. This only works for an administrator who has never completed password setup; existing active accounts cannot be taken over this way.
